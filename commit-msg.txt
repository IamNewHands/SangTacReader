补掉站点样式引擎在 iOS 分支里的崩溃：设置页不再透明压层、点得动

11 月那版前端在 app.v2.js 的 iOS 分支里调了两次 rootCss.update()，用的选择器
（"html,body" 和 "#overlay > div, .perf-div, ... #ctxoverlay ..."）从来没被
rootCss.set() 注册过。stv.ui.js 的 st.update() 直接取 this.collection[id] 再写
.css，id 不存在就是 undefined，于是抛
  TypeError: Cannot read properties of undefined (reading 'css')
抛出点在 app.platform 那个 IIFE 里，一抛就中断了它后面所有 IIFE：
app.theme / app.config / app.perf / app.images / app.fontmanager / app.namemanager
全部停在 undefined。主题变量因此一次都没写进 :root，--background 与 --bg-tps
是空串，而 #overlay 与 #overlay > div 的 background 是 var(--background) ——
var 展开成空值时该声明 invalid at computed-value time，等同 unset，也就是透明。
于是设置页下面那层用户 tab（头像、设置、登录）和 tabbar 直接透上来，看着像
「页面重叠、设置项点不了」。

只在真机上炸：app.v2.js:5379 是 if(window.Capacitor){ ... if(!isAndroid && !isIOS)
{ app.platform.isWeb = true; } }，有 Capacitor 且 platform 是 ios 才进这条分支，
桌面浏览器 isWeb 为真，根本走不到那两行。

改法（compat 块，注入最早，stv.ui.js 一到位就生效）：
- patchStyleEngine() 包一层 ui.style.create 返回的 sheet.update：collection 里
  没有这个 id 就先按值注册（字符串走 set，对象先建空壳），再交给原 update 合并。
  幂等标志 __stvStylePatched；ui.style 还没定义时每 10ms 重试，最多 2000 次。
- 顺手补 patchTextLoader()：shell 的 app.celoader.text 用
  eval("app.text." + ogText)，中文覆盖层把 ogText 改写成带空格或汉字之后这个 eval
  会抛 SyntaxError（切一次语言三条），节点保持旧内容。改成直接查 app.text[key]，
  查不到才回落到原实现。

验证（本地代理跑「线上 shell + 32 个注入块 + Capacitor 设备桩」）：
- 修前：compat:false、theme/config/images 全 false、--background 空、stv.ui.js:3213
  的 TypeError 照旧、设置页透明且点不到。
- 修后：patched:true、theme/config/perf/images/fontmanager/namemanager 全 true、
  --background=#ffffff、#overlay 子节点 rgb(255,255,255)，设置页 13 行里 11 行
  elementFromPoint 命中自身（另两行是隐藏行与屏幕外），SyntaxError 归零。

门禁：check-ios-shim ✓（32 块）、gen-site-i18n --check ✓、test-site-patch ✓。
