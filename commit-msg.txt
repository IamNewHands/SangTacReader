给启动装上可读的钟：分清「页面之前」和「页面之上」各花了多久

真机冷启动 10s、热启动 5s 这件事一直没法查，因为日志里根本没有能回答它的数：
BOOT 采样点只打 app/config/navbar 三件事（0/1/3/6/10/20s），全程都是
app=yes config=yes navbar=85px，看不出内容什么时候到位；[ASSET] 时间线统计的是
已经发出的请求，看不到「还没发出的等待」；而进程启动、bridge、webview 创建、
HTML 往返这一段发生在 document start 之前，页面侧一个字都记不到。

三处补上：

1) 首屏内容可见（bootShell 块）。#historyview 的列表由 app.init() 之后 fetch 并
   渲染（app.v2.js:4155-4181），封面再从另一个 CDN 主机取 —— [ASSET] 只统计同源
   请求，根本看不见封面。现在用 MutationObserver + 500ms 轮询盯住 historyview，
   第一次出现子节点就打
     [BOOT] first content at +Nms (mutation|poll, N node(s) covers=x/y)
   并且每个采样点后面都带上 content=N node(s) covers=x/y。框架起来和「有东西可读」
   从此是两个数，不是一个。

2) HTML 往返（同一个块）。shell 来自远端 server.url，等这段 JS 跑起来时启动已经
   过去一秒多了。用 performance.timing 打 navigation: html Nms，这是唯一能量化
   「网络那一秒」的数。

3) 原生那一段（SangTacAppPlugin）。插件在 load() 记下 systemUptime，getInfo 多回
   uptimeMs / loadUptimeMs 两个字段（它没有任何 JS 消费者，加字段安全）；页面拿
   自己的 performance.now() 去减，打出
     [BOOT] native: plugin loaded Nms before document start (page age Nms)
   冷启动里最贵的「页面还不存在」的那段第一次有了数字。
